## What it is

A GNOME Shell extension that replaces Ubuntu Dock with **Putty**: a small
floating, draggable, collapsible organic "blob" Node. Tap it to expand a
flattened-putty-shaped panel showing favorite apps (icon-over-label tiles,
2 rows) + running apps (icon+dot, no label) + a "Show Apps" tile that opens
the real GNOME app grid. Click outside, press Escape, or tap the Node again
to collapse. Enabling Putty disables Ubuntu Dock; disabling Putty restores
it to whatever state it was actually in before (doesn't resurrect a choice
you made yourself).

Originally a personal customization (not part of the private `modebi`
repo), formalized into this standalone public project per your request.

## Verified working live (2026-11-07/08, multiple logout/login test cycles)

- Drag Node anywhere, position persists per-monitor (by stable connector
  name) across logins, clamped on-screen during the drag itself (not just
  on release).
- Tap-to-expand/collapse, outside-click dismissal, Escape dismissal.
- App launch from favorites, running-app focus/activate.
- "Show Apps" tile opens the real app grid (`Main.overview.showApps()`).
- Ubuntu Dock auto-disable on enable, auto-restore on disable, correctly
  does *not* clobber a state you set yourself (ownership-marker logic in
  `dockOwnership.js`).
- Organic putty visual redesign: metaball-style SVG blob shapes for both
  the Node and the expanded panel, generated (not hand-drawn) from a
  centralized palette.
- Panel content (2-row favorite tiles + running row) renders inside the
  organic silhouette without spilling outside it, and is centered within
  it both horizontally and vertically.

## Architecture

- `extension.js` — lifecycle glue (`enable()`/`disable()`), monitor/work-area
  resolution, Node position persistence, Ubuntu Dock ownership side effects.
- `node.js` — the floating blob button: drag/click handling, clamps against
  the live work area during drag (not just on release).
- `panel.js` — the expand panel: modal grab/dismissal, app-tile layout,
  placement/flip.
- `nodePosition.js` — **pure**, zero-GNOME-import geometry (clamp, normalize,
  4-direction panel-flip placement). Also the single source of truth for
  `NODE_WIDTH/HEIGHT` and `PANEL_WIDTH/HEIGHT` (450×230), which must match
  the generated SVG canvases exactly.
- `dockOwnership.js` — **pure**, zero-GNOME-import decision logic for the
  Ubuntu Dock enable/disable ownership rule.
- `theme.js` — centralized putty color palette (hex constants). GNOME
  Shell's St CSS has no `var()`/custom-property support, so this is a
  manually-synced source of truth, not a live binding — both
  `stylesheet.css` and `scripts/generate-blob-svgs.mjs` read from it
  independently.
- `scripts/generate-blob-svgs.mjs` — regenerates `assets/node-default.svg`
  and `assets/panel-default.svg` from `theme.js` + the dimension constants
  in `nodePosition.js`. Run with plain `node` after editing either. Not a
  runtime dependency.
- `tests/` — `node --test`, covers the pure modules above. 11 tests passing.

## Hard-won gotchas (don't re-derive these)

1. **Wayland caches loaded extension JS modules in-process.** Editing
   `.js` files and running `gnome-extensions disable/enable` does **not**
   reload the code — only a full logout/login does. This cost most of the
   iteration time this session; budget for it on any future change.
2. **`Main.extensionManager.enableExtension/disableExtension(uuid)`**, not
   a `gnome-extensions` subprocess, for toggling Ubuntu Dock. Shelling out
   risks deadlocking GNOME Shell's single-threaded main loop (the
   subprocess's own D-Bus call needs that same loop to answer). Confirmed
   real by reading `ui/extensionSystem.js` directly — just flips entries in
   `global.settings`'s `enabled-extensions`/`disabled-extensions` keys.
3. **`Gio.Subprocess.communicate_utf8()` returns `[success, stdout,
   stderr]`**, not `[stdout, stderr]` — easy to silently grab the boolean
   instead of stdout. (Moot now since we don't shell out anymore, but
   relevant if that pattern ever comes back.)
4. **`Main.layoutManager.addChrome()` only accepts `trackFullscreen` and
   `affectsStruts`** (confirmed via `ui/layout.js`'s `defaultParams`) — any
   other key throws `Unrecognized parameter`, synchronously, inside
   whatever signal handler called it. No `affectsInputRegion` option exists.
5. **Under an active `Main.pushModal()` grab, clicks outside the grabbed
   actor's subtree aren't delivered as Clutter events at all** — not just
   misidentified, genuinely not delivered. A `global.stage` listener can't
   catch them. Fix: grab a full-stage-sized invisible root actor with the
   visible content as its child, so every click is legitimately "inside."
6. **St's `background-image` doesn't reliably stretch to an arbitrary
   allocated size** (no confirmed working `background-size: <percentage>`
   behavior). The image renders at its own intrinsic SVG canvas size
   regardless of the container. Fix: size the container (the `St.Bin`) to
   the SVG's actual canvas dimensions (`PANEL_WIDTH`/`PANEL_HEIGHT`), don't
   derive it from content.
7. **Verify GNOME Shell JS APIs against the real source before relying on
   them.** `gresource extract /usr/lib/gnome-shell/libshell-18.so
   /org/gnome/shell/ui/<file>.js` dumps the actual bundled source (also
   `layout.js`, `extensionSystem.js`, `overview.js`, `params.js`,
   `appFavorites.js`, `animationUtils.js` worth knowing about). Paired with
   standalone `gjs`/GI introspection checks (needs
   `GI_TYPELIB_PATH=/usr/lib/x86_64-linux-gnu/mutter-18:/usr/lib/gnome-shell`
   and matching `LD_LIBRARY_PATH`) and `GdkPixbuf`-rendered SVG previews
   (same librsvg backend GNOME Shell itself uses), this caught several real
   bugs *before* burning a logout cycle on them.

## Known limitations

- Personal-use distribution only — not submitted to extensions.gnome.org
  (would require `gnome-extensions pack`, GPL-2.0-or-later compliance
  review, and a permanent UUID commitment; `putty@paperweighthq.com` is
  already a real domain you own, so it's ready if you ever want to).
- No real screenshot/gif in the README yet (still a `TODO` placeholder).
- Panel background won't stretch if content ever needs to grow
  significantly beyond the 450×230 design canvas (see gotcha #6) — fine at
  current favorite/running-app counts, would need revisiting for someone
  with a lot more pinned apps.
